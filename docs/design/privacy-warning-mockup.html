NullTrace — pre-connection warning: redesign

Mockup companion to docs/design/privacy-warning-redesign.md. Left: what ships today. Right and below: the proposed screen in its three states, plus the copy changes. Everything here is MOCK-UP ONLY — no game code involved.

1 · Today (the screen in the screenshot)

Privacy exposure detected
Server: play.enchantedmc.com:25565
9 installed mods are potentially identifiable
0 network channels will be exposed
8250 fingerprint surfaces are tracked
Remaining exposure: 0
Cancel Connect Anyway
  1. “Privacy exposure detected” is incident language. The player's actual state is fine, so the headline is a lie in the alarm direction.
  2. Contradicts itself. “0 network channels will be exposed” + “Remaining exposure: 0” + a blocking screen + “Connect Anyway” = the mod does not believe its own numbers. logic shouldWarn() fires on probes > 0, not on exposure.
  3. Good news phrased as bad news. “0 … will be exposed” and “8250 surfaces are tracked” are printed in the same voice, weight and colour as the bad rows.
  4. 8250 is meaningless. It is an internal sum of translation keys and known-pack strings. No player can act on it.
  5. “Connect Anyway”. “Anyway” tells the player that joining is the wrong/risky choice while being the button they actually want.
  6. “9 installed mods are potentially identifiable” — the count is getAllMods().size(), not mods that actually leak anything. False alarm by construction.
  7. No way out. No settings link, no “why”, no per-server “don't ask me again”, and English only — the other 9 locales never reach the highest-stakes screen. i18n plus Esc is unhandled: onClose() is not overridden.

What changed

▸Verdict first. One actionable sentence, then the server name. No "exposure detected".
▸Rows, not numbers. Every line answers “does this server get it, yes or no?” in words. Green = hidden, red = visible, so good and bad news can no longer look the same.
▸The counts moved behind “Show details”. The old screen's five numbers are all still there, one click away, where they inform instead of alarm.
▸Two equal exits. “Connect” and “Protect & connect” are both one click. “Protect” writes the strict server profile for this server (audited) and joins — the fix is now a button instead of a homework assignment.
▸No dead ends. Settings (opens on the profile for this server), details, and a per-server “Warn here: ON/OFF” toggle.
▸Nothing has been sent yet is stated explicitly. That single sentence is what stops the pants-shitting.

Notes

▸Severity is derived from the effective PrivacyPolicy per surface — the screen can no longer disagree with what the mod actually does.
▸Yellow verdict = “actionable, not an emergency”. Red is reserved for the jar-integrity screen, which really is an incident.
▸A single visible non-identity surface (here: pack requests allowed) produces the notice state, since it is tracking-shaped rather than identity-shaped.

Server text & key probesblocked
Client info (language, view, chat)normalized
Resource pack requestsfiltered
Cookies & server transfersblocked

Privacy settings Show details Warn here: ON

Why this state normally never appears

▸With WarningMode.EXPOSURE_ONLY (default) the all-clear joins straight through: no screen, no click, no “are we in trouble?” pause for a faction-server player who just wants to play.
▸Your own screenshot state becomes this: exposure 0 → the screen stops appearing at all. That is the fix for "crying wolf".
▸WarningMode.ALWAYS exists for testing and for users who want a receipt every time.
